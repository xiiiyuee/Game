## 2. A 计划架构摘要

```
玩家 A（房主）
  ├─ 运行完整模拟（30Hz）
  ├─ 本地渲染
  ├─ DataChannel ── 玩家 B
  ├─ DataChannel ── 玩家 C
  └─ DataChannel ── 玩家 D

信令服务：只交换 SDP / ICE
TURN：只在中转流量时使用
```

核心原则：

- 房主权威：敌人、Boss、子弹、伤害、掉落、升级结果全部由房主裁决。
- 客户端只发输入、收快照、做表现。
- 粒子、浮动文字、震屏、音效、星空只在本地生成，不同步。
- 快照 15Hz，输入 30Hz，本地玩家预测 + 远端插值。
- 关键事件走可靠通道，快照和输入走不可靠无序通道。
- 只同步视野附近实体（兴趣裁剪），不要全图广播。

A 计划的硬限制：

- 房主必须保持前台，切后台会暂停全场。
- 房主天然低延迟，且可作弊，只适合朋友局。
- 房主退出等于解散房间，不做主机迁移。
- 房主上行带宽和性能是人数上限，建议 4 人以内。
- 国内网络需要 TURN 兜底，纯 P2P 成功率不够。

## 5. 风险清单

| 风险 | 影响 | 规避 |
|---|---|---|
| NAT 打洞失败 | 部分玩家永远连不上 | 必须部署 TURN；失败提示清楚 |
| 房主切后台 | 全场卡住 | `visibilitychange` 广播暂停遮罩 |
| 房主上行不足 | 人多就卡 | 兴趣裁剪、快照量化、限制 4 人、桌面房主 |
| 升级/商店暂停 | 一个人卡住全队 | 个人弹窗、世界继续、限时自动选择 |
| 射击延迟感 | 手感差 | 自己子弹本地曳光预测，房主裁决命中 |
| 浏览器差异 | Safari 连不上/卡顿 | Safari 单独测；DataChannel 参数保守 |
| 国内网络 | P2P 成功率低、TURN 流量成本 | 提前接受 TURN；必要时换更稳的中转 |
| 重连缺失 | 掉线只能重开 | MVP 先接受；Alpha 后补 60 秒重连 |
| 单文件过大 | 改动互相影响 | 先抽 `simulate`/`input`/`render`，保持单文件但分层 |
